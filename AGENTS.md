# Background work by default

- Work entirely in the background unless the user explicitly asks otherwise.
- Do not switch the user's active chat, bring apps or windows forward, or open visible browser tabs, previews, files, or review panels unless explicitly requested.
- Use background tools and hidden or headless browsers for testing. Do not take over the user's active browser tabs.
- Return links and results in the current chat without opening them automatically.
- If a step requires taking over the screen or changing focus, ask first and continue independent background work while waiting.

# Coding and review discipline

Ponytail is installed for this project. Use the `ponytail` skill in full mode for every coding, fixing, refactoring, and implementation-design task. Follow its ladder: understand the complete affected flow, reuse existing project patterns, prefer standard-library and native platform behavior, use installed dependencies before adding new ones, and write the smallest correct change.

For every code review, run both:

1. the normal correctness, security, privacy, accessibility, performance, and regression review; and
2. `ponytail-review` for a separate over-engineering and deletion pass.

Ponytail never permits simplifying away input validation, authorization, row-level security, privacy controls, accessibility, data-loss prevention, error recovery, or explicitly requested behavior.

Every non-trivial logic change must include the smallest runnable automated test that would fail if the behavior regressed. Finish and test each affected piece before dependent work. Preserve the full product goal; an internal milestone is not a launch claim. Reuse proven patterns and extract shared code when actual routes demonstrate the need, rather than building a speculative agent/connector platform. A provider failure changes a route dependency within a committed workflow; do not restart the app, theme or Auth, silently substitute a finder/document for confirmed help, or discard PECO/COMPASS work.

At major checkpoints, separately compare the direction with the goal of maximum useful family-service autonomy. Record family work removed, remaining or new prompts and their actual reasons, routine work still done by people, the outcome proved and the next smallest change toward autonomous completion. Internal rehearsal pauses must not become product requirements or count as provider-required family participation. # Product north star

CaseLink is a direct-to-parent **family-support service** designed for maximum useful AI independence. The October 27 staged plan launches R1 with confirmed food access and one adult career-support booking lifecycle, expands R2 to complete food/utility C-01, then R3 to the original catalog. After minimum intake and one informed, bounded authorization, AI makes routine judgment calls and pursues supported work through an outcome. Parents own their accounts and control the mandate. Every released workflow must be polished and ready for families, with human participation only where actually necessary or chosen by the family.

Current product authority is `docs/parent-support-mvp-prd.md`; delivery order and phase gates are in `docs/parent-support-implementation-plan.md`. See `docs/README.md` for document precedence. These are requirements, not claims that the parent features are implemented. Older school-pilot requirements, runbooks and verification records describe the legacy app and do not override this pivot or certify the parent product.

Use this north star when making product, design, and technical decisions:

- Prioritize minimum intake → one informed service mandate → autonomous judgment and permitted execution → necessary personal steps only → continued follow-up → attributed outcome.
- R1 requires both real food allocation/access and adult career-support booking, including receipt, changes/follow-up and attributed collection/attendance. R2 preserves immediate food, SNAP new/renewal/pending/routine problems, relevant WIC journeys, electricity/gas/water assistance, shutoff/disconnection and combined needs. R3 maps the remaining catalog. This staged release decision supersedes all-C-01-before-first-family-release; an internal slice still is not a release, and R1 is not complete C-01.
- Deliver complete Get support, My support, Request detail, account/recovery, mobile document capture/manual alternatives, meaningful progress, notices, privacy/control/help and return-use experiences. Include all loading/empty/waiting/error/success states, visual/accessibility/language QA and family observation; no placeholder or hidden routine operator workaround qualifies as family-ready.
- Use GPT-6.1 Sol (`gpt-6.1-sol`) through Responses as the driver. Reuse the stack, validation, source grounding, budgets and tests. A coordinator can use specialized tools/workers/agents where useful; avoid a speculative general agent platform.
- AI may prioritize, interpret validated evidence, choose compatible programs/authorized recipients, complete known forms, execute provider-permitted referrals/applications/scheduling, supply authorized information, check real status, follow up and try permitted alternatives independently.
- The start mandate specifies individually named recipients/programs, purposes, actions, data/document use, preferences, concrete limits, duration and revocation. Server code checks the exact operation and current mandate/provider authority at every side effect; in-scope packet updates, supplements and follow-ups do not require repeated parent approval.
- Ask a person only for an indispensable unresolved fact, expanded permission, required personal authentication/identity/signature/attestation, meaningful financial/personal choice, qualified legal/clinical judgment or an execution/safety issue AI cannot reliably resolve. Prepare everything else, pause only affected work, record the reason and resume afterward.
- Forms, permitted application submissions and tested browser assistance are in scope. Honor provider/tool requirements for human involvement in authenticated or hard-to-reverse browser work; no impersonation, invented signatures, bypassed controls or unapproved binding financial commitment. Do not imply integration permission or successful action without evidence.
- Distinguish preparation, transport acknowledgement, partner receipt/acceptance, agency submission, assistance approval and support actually received. Attribute parent or operator reports honestly.
- Treat household information and documents as sensitive. Enforce parent ownership, referral-scoped partner access, minimal data, traceability, revocation and deletion. Existing school staff/admin roles must not inherit parent access.
- Apply the dated applicability and evidence gates in `docs/parent-privacy-regulatory-review.md`. WIC/pregnancy collection requires a documented FTC health-record assessment; HIPAA, COPPA, FERPA and agency confidentiality depend on actual roles and data flows. Never claim legal compliance from code or synthetic tests. Enforce processing closure in database/Auth policies as well as the web app, keep processor retention distinct from CaseLink deletion, and recheck current law and contracts before real-family intake.
- Preserve the school environment and records. A parent-specific processing path must not globally remove existing identifier, authorization, session or deployment guards.
