# Parent application workspace checkpoint

Verified October 26, 2026. This implements the approved storyboard’s workspace and interaction changes on `main`; it does **not** complete autonomous benefits filing. The current background localhost preview reuses existing CaseLink identities within the previously approved window ending **October 27, 2026, 12:54:27 p.m. EDT**. Public enrollment and external application transports remain disabled. No pilot extension, shared Auth setting change, new production credential, or public deployment was made.

## Implemented behavior

- Generic food and utility entry require explicit selections. SNAP household/income and utility information are grouped before the bounded mandate; uncertain optional details can remain blank. Back preserves answers. Required sensitive identifiers remain a separate, unfinished protected-channel requirement.
- Request detail has a responsive, clickable checklist and distinct application, next-step, document, receipt and permission sections. Sections stay mounted so navigation preserves drafts. Paused requests retain Resume and history without presenting active completion/upload controls.
- Submission statements use recorded operations for the exact program, need and applicable request version. Guidance is distinct from a prepared application artifact. Uncertain/executing delivery prevents duplicate encouragement. Older or incomplete history cannot prove that no application was submitted. The endpoint fetches 101 records to identify a limited 100-record display; full retained history remains in the account export.
- Recorded approval, support received and declined results lead to the outcome/receipt and follow-up details. Required personal steps take precedence. A renewal receipt cannot establish a new SNAP filing.
- Floating chat uses a desktop window and phone modal with minimize, Escape, focus return, retained unsent drafts, keyboard sizing and boundary navigation. Its saved-request answers retain the existing consent, ownership, grounding, cancellation and history controls. SNAP chat separately displays the current owned website-view record; this does not imply that the model has agency account access.
- Automatic execution now checks application readiness at its existing dispatch boundary. A routine review click is unnecessary when the exact operation has valid authority, verified required facts/form, a connected permitted transport, and any applicable evaluated decision evidence. There is no invented model confidence percentage or calibrated score in the current pilot. Model confidence cannot replace facts, provider permission or a required personal act.
- ZIP/language controls align despite unequal help text. The original CaseLink identity, imagery, recognition banner, typography and policy links remain in place. Summary PDFs now call plan-only preparation “Guidance ready.”

## Real website view and its limit

The private loopback service on port 3330 runs the installed Playwright browser in nonpersistent, separate contexts. The web runtime receives no model, database or administrative key. Only the verified parent’s short-lived token is forwarded; the private service independently rechecks live identity, processing access, owned household/request, current mandate and request version before actions and frames. It reads selected support needs instead of the complete household intake.

The browser follows only the reviewed public COMPASS start-page recipe. Main-frame navigation is restricted to COMPASS; CAPTCHA dependencies are limited to reviewed Google/gstatic paths. Websockets, downloads, popups and service workers are disabled or denied. Input fields and iframes are masked before JPEG delivery. Frames are authenticated, same-origin and private/no-store. No household values, credentials, signatures or SSNs are entered. Tokens/frames stay in memory and are erased when the context closes; sessions last at most ten minutes and are also bounded by JWT, mandate and pilot expiry. Revocation/version changes close ongoing work without requiring the page to remain open.

The independent live runner reached the actual Family Safety screen and obtained a real masked JPEG. A separate live navigation check at **18:38 UTC** reproduced DHS’s visible verification failure without applicant information, registration, CAPTCHA solving or submission. The final implementation classifies that result as **Blocked**, closes the context and explains that the parent’s separate official-site session cannot be resumed through this viewer. It does not call this an actionable handoff or personal identity step. Failed Start/Stop connections return errors; a timeout cannot acknowledge a successful stop.

The real runner was checked directly with synthetic local authority, not through an eligible original-account JWT. Ownership/closure and API boundaries have automated tests, but that combined live viewer authentication path remains unverified. Existing-account eligibility was not broadened to create a new hosted test identity.

**Release blocker:** protected identifier capture/vault or approved provider entry, a genuine verification handoff/resumption, current conditional application fields, permitted delivery/certification, exact official receipts, and actual agency status/follow-up connections remain required. `PARENT_TRANSPORTS` is still empty. The viewer cannot fill or submit an application. This gap remains part of the full product scope; the public-page viewer is not a substitute for it.
