# Optional description usage accounting — closed engineering checkpoint

November 18, 2026. No model call, key inspection, processor setting, purpose/notice activation or spending authorization is established here. The separate 37/38-path description flow remains immutable; this patch composes only the narrow usage writer/schema and fixed dispatched pricing tier.

The current [official prompt-cache usage contract](https://developers.openai.com/api/docs/guides/prompt-caching) reports cached input reads, total cache writes and disjoint 30-minute/12-hour write counts. Both lifetime counters are reported even when zero. The old strict cached-only parser rejected this legitimate response as unknown. The revised parser requires these current Sol counters, checks integer bounds, total input/output consistency, lifetime sum, disjoint cached/write input subsets and reasoning as an output subset. Missing, contradictory or unrecognized counters remain unknown. No count is clamped or replaced by an invented zero.

The additive SQL writer keeps exactly these subset counters in the existing original-48h owned call evidence. Its existing worker-only grant, exact charge token, first-write-only behavior and late-cancellation accounting remain intact. Legacy retained records are not rewritten or assigned absent counters. Current new Sol dispatches require complete write counts. Exports preserve the recorded fields; content deletion never refunds an anonymous reservation. This adds no charge, permission, retention or retry mechanism.

The fixed evaluated request now includes `service_tier: "default"`. The current [Responses contract](https://developers.openai.com/api/reference/resources/responses/methods/create) distinguishes this Standard selection from omitted/auto project settings. Because the exact request object is in the fingerprint, old evaluation/health evidence cannot certify the changed setting. The later runner must also validate the actual returned model/tier and approved project/region; an unexpected/unknown billed category retains its reservation and stops the run.

The current [Standard Sol price table](https://developers.openai.com/api/docs/pricing) lists dollars per million tokens: ordinary input2, cached read0.10, 30m write2.50, 12h write5, output10. Cached/write categories replace ordinary input pricing; they are not extra input. Ordinary input equals input minus cached reads minus total writes. The write lifetimes sum to total writes and are counted once. Reasoning is included in output and is not charged a second time.

For a future reviewed runner bounded to80 Responses calls, each with at most8000 input tokens and1500 total output tokens, reserving every input token at the most expensive published Standard write rate yields80×(8000×5+1500×10)/1000000 =4.40 dollars in model tokens. This is a conditional arithmetic bound, not a completed runner guarantee or cash quote. Exact pre-dispatch input counts must use the [supported input-token count endpoint](https://developers.openai.com/api/reference/resources/responses/subresources/input_tokens/methods/count), including the actual model/input/instructions/reasoning/structured schema. Character estimates and post-response validation cannot cap prior spending. Global Standard region/contract and counting-request billing must be verified before approval; premium tiers/regions are outside this rate card. Taxes, account fees and credits are separate.
