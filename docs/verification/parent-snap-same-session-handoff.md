# SNAP milestone B: same-session verification handoff

Checked October 26, 2026 (America/New_York). This is a restricted connection rehearsal, not a family release or an application-filing milestone. The source implementation supports a parent-controlled public COMPASS verification surface and automatic recognition of the next screen in the same owned browser context. Actual provider acceptance remains an independent evidence gate.

Follow-up: the [current public-contract investigation](parent-snap-verification-investigation.md) found and corrected a missing normal Next after genuine verification completion. This record's original toy replay navigated directly after its synthetic interaction and did not prove that extra transition. The corrected replay explicitly enables Next, requires CaseLink to click it, and records its separate results and reliability limits.

## What changed

The private runner exposes only bounded public actions: the reviewed introductory Next button, a pointer inside a visible reviewed Google verification frame, a short native-key allowlist and a refresh/check. It accepts no arbitrary URL, script, text, applicant value, file, cookie or browser-control credential. The actual current parent/request/mandate authority, original deadline, session, delivered image nonce and current public target are checked before every input. A changed view is a recoverable stale response rather than a repeated action.

The family window waits for its exact image to load, preserves Stop while an action is pending or a transient metadata read fails, offers native keyboard controls and a contained enlarged view, and disables input after expiry or image failure. A genuine challenge appears in the request's main next-actor label and clickable checklist; the internal preview continuation does not. Completing a supported check requires no additional confirmation button. CaseLink observes the provider result and follows only the exact reviewed public ending/divider controls. It waits for SPA hydration, recognizes the precise blank first-person household form, then closes the context without entering or capturing protected fields.

Metadata polling and the private sweep update asynchronous challenge images. An unchanged image and target retain their nonce; changed pixels/geometry/frame identity invalidate the old image. A command rechecks the current snapshot before input. Frame delivery itself does not recapture or silently change the nonce it is serving. Cancellation, revocation, request changes, account/session closure, expiry and bounded interaction limits retain their stop/erase behavior.

The UI calls this result **Connection check complete** and explicitly says that nothing was filled or submitted. The checklist callback reflects only the open request's ephemeral browser state. It does not make that state durable or automatically connect it to My support cards or the AI assistant.

## Evidence boundaries

1. Engine and policy tests exercise nonce delivery/replay, target and pixel changes, concurrency, bounded input, ordinary public resumption, delayed page rendering, Stop, cancellation, authority changes and expiry. Test metadata and provider replay are labelled fixtures.
2. Actual isolated Supabase Auth/RLS and the native private HTTP server test real password sessions and ownership, strict Host/Origin/path/body/schema rules, foreign/anonymous/retained sessions, closure and exact cleanup. No hosted controls or original account cohort are changed.
3. The combined candidate test uses the actual Next sign-in route/cookies, real local Auth/Data API and the actual private runner/HTTP relay. All COMPASS/Google responses in this test are explicitly fulfilled in-memory replay pages; no DHS or Google traffic, applicant fields or government filing is permitted. Passing it proves the app handoff mechanism, not live provider acceptance.
4. Live public navigation is recorded separately from replay. A separate ordinary browser reaching a blank form does not establish that the private service browser can do so, and no cookies or provider credentials are copied between them.

The isolated test copy uses web port 3201 and private port 3331. Its only application-source override is the private loopback port. The existing account preview on 3200/private browser on 3330 remains independent. Test fixture credentials remain in process memory; exact disposable identities/requests are removed and local processing controls restored before a passing report is written. No model calls are required for this deterministic connection piece.

## Goal-alignment review

- **Family work removed:** no separate tab/cookie transfer, manual post-verification navigation, extra 'Check and continue' ceremony, or manual refresh to see asynchronous challenge updates. The service follows reviewed routine public transitions itself.
- **Family prompts remaining:** the Family Safety Continue pause is an internal rehearsal control, not evidence that every applicant needs a personal act. An actual provider verification challenge requires the family because software must not solve or bypass it. Unsupported typing/audio checks and inaccessible remote challenges need a verified alternative; they are not resolved by the current image/keyboard surface.
- **Work still done by people:** development-time provider inspection, permission/field/certification contract verification and any unresolved provider acceptance. No operator filing is counted as autonomous completion.
- **Outcome actually proved:** recorded in the final results below. Reaching an empty form is a connection result, not a drafted, filed, accepted or approved SNAP application.
- **Next smallest autonomy step:** after live same-session acceptance, verify the complete conditional SNAP-only fields and permitted certification/delivery contract, then build one protected information bundle that reuses known facts and asks necessary missing questions together. The mandate should eventually start supported work; opening the viewer should inspect it. Protected identifiers, permitted filling/filing, real receipts/reconciliation, durable status, interviews/documents and outcome follow-up remain required service work.

Normal correctness/security/privacy/accessibility/regression review and a separate Ponytail deletion pass are required for each piece. The periodic goal-alignment review is now recorded in AGENTS.md and the implementation plan; it cannot redefine a connection rehearsal as the finished autonomous product.
